# 介面與維護準則

讓同事找到手上的工作、理解原因，然後知道下一步。以 DESIGN-cohere.md 的配色與字體方向，以及 COO-UI-BASELINE.md 的任務優先、漸進揭露、回復能力和即時回饋為基礎；原文與決策見 research/product-design.json。

## 外觀

- 淺色：白底、近黑主文字、石色概念區、節制的藍色操作提示。深色：墨綠背景與較亮的文字／操作色。
- 共用色彩、間距、圓角與動態 token 在 web/style.css。先改 token，再檢查各元件，避免逐頁覆蓋。
- 預設跟隨作業系統，使用者可選淺色、深色或回到跟隨系統。偏好存於 localStorage；主程式載入前先套用，減少錯誤色系閃爍。
- 英文標題用 Space Grotesk、介面用 Inter，中文字使用系統字體。字型本地載入並附 OFL 授權，不依賴第三方字型請求。
- 文字對比以 4.5:1、必要控制／焦點以 3:1 為基線；每次改色都檢查兩種主題。這是局部對比檢查，不能取代完整無障礙稽核。

## 閱讀與互動

- 維持「概念 → 影響 → 重點 → 例子 → 第一步 → 完成」順序。來源與交接表單在後段展開。
- 全站搜尋可按 ⌘K／Ctrl K。搜尋結果可用方向鍵、Enter 與 Escape；手機提供有名稱的搜尋圖示。無結果時提供縮短詞彙或完整搜尋入口。
- 搜尋在中文組字完成後更新；60ms debounce，預先正規化資料，批次更新結果。以文字節點標記命中詞，不插入使用者 HTML。
- hover、pressed 與面板過渡維持 150–200ms。焦點始終可見；尊重 reduced-motion，不用持續動畫打斷閱讀。
- 手機導覽開啟時背景 inert、焦點留在導覽內；關閉後回到觸發按鈕。主要觸控操作至少 48px。
- 草稿、知識選取、展開狀態、閱讀位置與焦點只保留在此分頁的 sessionStorage，最多 20 頁。關閉分頁後不保證保留；不同分頁不做同步。
- 清除本頁草稿可立即撤銷。儲存被瀏覽器阻擋時顯示下載提示；複製失敗則選取完整文字。未知專案欄位維持「待補」。

## 變更驗收

1. 修改 canonical content／web／scripts，重新 build、執行 harness 及兩份 JavaScript 語法檢查。GitHub workflow 重跑相同檢查並驗證生成檔一致，不部署。
2. 依影響檢查主閱讀路徑、深連結、搜尋／中文輸入、手機導覽、主題保存與草稿撤銷。封包變更要真的下載並比對內容。
3. 版面變更檢查 390px、1024px、1440px；必要時加 320px。視覺檢查等待過渡完成，記錄瀏覽器縮放，避免把自動化座標問題當成產品缺陷。
4. 保留 no-JS 閱讀、file URL、列印與 reduced-motion。資料改動檢查來源範圍；綠燈不能代表專業內容已獨立認證。
5. 效能比較記錄同一頁的資源 bytes；本機載入時間不當成正式環境 Core Web Vitals。搜尋 payload 上限 70KB，完整匯出 corpus 上限 240KB。
6. 有相關變更或新失敗才重跑已通過的項目。收據只記實際執行結果，舊版證據保留歷史標記。

## 發佈邊界

GitHub 原始碼同步與網站部署是兩件事。此專案沒有登入服務；noindex 也不是權限控制。加入私人專案內容前，先確認 repository 與日後 hosting 的存取範圍，並將所有 HTML、搜尋資料與下載檔一起保護。
