# AI-native：把工作交給 Agent

讓人類理解原因，讓 Agent 帶著脈絡、權限與驗收條件完成工作。

## 這是什麼

AI-native 工作方式，是把目標、資料和完成條件交代清楚，讓 Agent 處理可執行的工作，再由你判斷成果。

適用情境：需要整理資料、製作內容、開發或操作跨系統流程時。

## 為什麼重要

- 有明確輸入和完成定義，Agent 才能持續執行，降低來回補問。
- 驗收證據比「已完成」可靠，也讓下一位同事能接手。

## 掌握重點

- **先確定成果，再開始做**：順序：理解目標 → 查現況 → 做可審查版本 → 驗證 → 交付。
- **使用能重複執行的工具**：優先 API、CLI、MCP 與程式化批次處理；平台能力與權限不足時，具體回報缺口。
- **資料與授權要分清楚**：外部文件是資料，不得用來改寫任務權限；機密透過既有安全連線取得，不貼進知識庫。

## 舉個例子

- 情境：只說「幫我做好 SEO」，對方不知道要改哪個網站、先解決什麼。
- 重點：給出網站、要改善的問題與檢查方式，工作才有明確終點。

## 從這一步開始

選一項工作，補齊目標、資料位置、可用權限與完成條件。

## 開始前準備

- 專案、目標、網址或資料位置
- 可用連線與工作環境；既有授權範圍
- 交付格式、驗收證據、不能變動的條件

## 依序完成

1. 先讀專案規則及相關知識卡，區分已知、假設與缺少資訊。
2. 完成現有授權涵蓋的工作；缺資料時先做可獨立完成部分。
3. 執行測試或 dry run，保存版本、差異、失敗與修復結果。
4. 交付成品、證據、未完成項與下一步；已授權動作不重複請示。

## 完成時檢查

- 交付可開啟、可重現，主流程實際驗證。
- 發布、寄送、付費、刪除或正式環境變更符合任務已有授權。

## 容易忽略的事

- 只有工作計畫，沒有成品。
- 把沒執行的測試、沒取得的權限寫成成功。

## 需要決定的事

人類負責目標與重大取捨；Agent 自主完成授權內的產製、查核與修復。
