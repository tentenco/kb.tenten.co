CMS、內容模型與多語系

讓內容能被一致地編輯、重用、預覽與安全發布。

先懂概念掌握重點開始做確認完成

先理解

這是什麼？

CMS 是管理網站內容的地方。內容模型把文章、商品、案例等拆成有規則的欄位，讓同一份資料能在多處重用。

什麼時候用

編輯更新很慢、同一資訊在多頁不一致，或需要多語網站時。

為什麼重要

  • 結構化內容減少重複輸入，也讓 Agent 能批次整理及驗證。
  • 內容有來源、版本和負責人，才不會搬站後變成無人維護的資料。

掌握概念

記住這 3 個重點

  1. 先定義內容，再決定欄位

    先定義文章、服務、案例、商品等內容類型，再定欄位、關聯與驗證。

  2. 多語系不只是翻譯文字

    多語系要定市場、URL、fallback 與翻譯狀態；事實共用、文案依市場調整。

  3. 編輯、預覽和發布有不同責任

    預覽、發布、審稿和媒體授權要有責任；API 權限與前端顯示分開。

名詞小抄 2 個名詞
CMS
Content Management System，管理與發布內容的系統。
Fallback
指定內容缺少時，改用哪個備用版本。

用情境理解

舉個例子

產品名稱出現在首頁、比較表和文章中，卻各自手動輸入。

這時要掌握的是

把共用資料集中管理，更新一次就能保持一致。

接著開始做

從這一步開始

選一種常更新的內容，列出欄位、來源與使用位置。

開始前，準備這些資料 2 項
  • 內容與 URL 盤點、欄位與素材
  • 語言市場、編輯流程、既有 CMS 與整合
  1. 建立 schema、範例記錄、來源對照與必要欄位驗證。
  2. 用可重跑轉換處理內容、媒體和關聯，先 dry run。
  3. 檢查數量、內容、URL、預覽與權限，再交付編輯流程。

怎麼知道完成了？

  • ✓重要內容可從舊記錄追到新記錄；缺項有清單。
  • ✓未發布內容不被公開 API 或搜尋意外讀取。

需要決定的事

確認誰負責內容、誰能發布，以及哪些變更需要審查。

容易忽略的事

  • 把每頁整包 HTML 當成唯一內容模型。
  • 只比記錄數，沒有確認圖片和關聯。
